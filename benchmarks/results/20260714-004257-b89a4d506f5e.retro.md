## Candidate items

### RETRO-1 · Phantom frontend port in single-process apps silences UI test failures

- **Proposed:** P1 · Effort M · Risk MED
- **Problem:** The harness invents a free port for "frontend" even when the project template explicitly says "Frontend URL: N/A — same Flask server serves the page". For single-process apps (Flask/Django/Rails), nothing ever listens on the phantom port, causing browser-QA to skip all tests silently while the app is healthy on the backend port. The failure is invisible: artifacts exist, review/QA pass, but DoD results show 0/15 tests.
- **Evidence:** Lessons tail — "The harness invents a frontend port for every project (`common.sh:357`, `_find_free_port $((3000 + offset))` -> `:3904`) even when `.claude/project-template.md:53` says 'Frontend URL: N/A — same Flask server serves the page'. For a single-process app nothing ever listens there, so browser-QA probes a dead port, reports 'frontend not running', and SKIPs all tests while the app is perfectly healthy on `:5177`."
- **Sketch:** Teach the harness to read `.claude/project-template.md` Frontend URL field before allocating ports. For projects with "N/A" or "same server", pass `--base-url <backend-url>` to all UI agents. Add a preflight check in the iteration entrypoint that logs which URL browser-QA will probe; fail loudly if port is unreachable, do not silent-skip.
- **Verify idea:** Run goal mode on a Flask/Django single-process project; confirm browser-QA reports pass/fail on actual test results (not SKIP), and the demo_runner uses the correct backend URL.
