### RETRO-1 · Deterministic gate must distinguish stub result files from clean passes

- **Proposed:** P1 · Effort M · Risk MED
- **Problem:** The browser-qa results gate (`goal_gate.py results`) decides PASS/FAIL by searching for `| FAIL |` table cells, so a crash stub with no table at all returns exit 0, vacuously reporting "no FAIL cells." An evaluator cannot distinguish a real all-passed run from a missing/failed report.
- **Evidence:** Lessons tail — "The deterministic gate therefore reports a browser lane that never wrote a result as *clean*, vacuously. It cannot distinguish 'all journeys passed' from 'the report is missing'."
- **Sketch:** Make `goal_gate.py results` exit non-zero (or a distinct exit code) when the results file carries a SKIPPED/stub marker rather than a real results table. Update evaluator to treat this distinct code as evidence that the lane was incomplete, not passed.
- **Verify idea:** Run a session where browser-qa crashes before writing a result, confirm the gate now fails the iteration rather than reporting GOAL_ACHIEVED on a missing report.
