## A. Executive diagnosis

The five reported problems are four framework-level causes wearing different symptoms.

1. **Governors read proxies instead of facts.** The evidence backstop (`run-goal.sh:2745-2775`) decides "no build work" from journey *status* (evaluator-written) and never reads the spec's `## IN SCOPE` body, although the parser for that body already exists (`goal_new_fullstack_journey`, `lib/common.sh:1400-1474`) and is used on the promotion rung. The browser lanes execute journeys from `docs/goal.md` and never see the spec's `## OUT OF SCOPE` constraints. The pump helper claims dispatch requests from any engine because no request carries an engine identity. In each case the control is one hop away from the thing it governs, so a true fact (a fix is listed; a journey mutates state; the engine that posted this request is dead) cannot influence the decision.

2. **Ownership is implicit, so cleanup is a matter of luck.** Ports are shared per checkout (`_project_port_offset`, `lib/common.sh:322-328`), services are killed by port or by command-line pattern (`kill_phase_servers`, `_bqa_kill_port_servers`, `reclaim_canonical_phase_ports`) with no owner check, `engine.pid` is removed unconditionally by any engine's EXIT trap, the dispatch channel is wiped before the lock is taken, and nothing (not `.awaiting-pump`, not `req.*`, not iteration markers, not service processes) carries an engine token. The one artifact class that is owner-guarded (`chain_tmp_cleanup`, `release_engine_lock`, `qa_browser_reap_on_exit`, `hg_release`) never bit. Git makes it worse: `runs/` is not ignored and `git add -A` is the publisher, so lock dirs, pid files, heartbeats and a flock target ship as certified evidence.

3. **Lifecycle transitions are half-typed.** `parked_wip_sha` has a writer and no reader; STALLED advances `current_iter` before halting and then dirties the tree again with halt bookkeeping; the resume status reset omits STALLED/BUDGET_EXHAUSTED/ABORTED; the hash-window stall detector never acknowledges a resume; and because executors run as foreground children, bash defers the engine's TERM trap until the child exits, so a clean pause degrades into SIGKILL and an orphaned executor that later runs its own cleanup against a newer engine. Each transition was implemented as a write without the matching read.

4. **Human decisions are prose, not records.** Owner rulings live in `assumptions.md` paragraphs, `docs/goal.md` amendments and `iteration-state.md` bullets. No decision has an id, inputs or a resolved flag the engine can check, so the AG-19 question was asked at iterations 6, 7 and 8, and the two-key confirm rejected on it. Operational pauses (pump loss, budget cap, disk) and genuine owner decisions share one channel (a status string plus narration), so the pump cannot tell "resume me" from "decide this".

Everything in section D follows from these four: give governors the fact (WP1–WP3), give artifacts an owner token and a single cleanup authority (WP4–WP7), give every halt write a resume reader (WP8), give decisions ids (WP9–WP10), and make the lessons structural so they outlive this plan (WP11).

### WP4C / HARD-4C — Orphan detection and sweep (token-based kill; legacy heuristics report-only)

1. **Problem.** After an unclean engine death (SIGKILL, crash), executors, waiters, workers and services of the dead engine keep running against the same session dir, channel and ports; the resume preflight (`:285-317`) reaps only a prior *engine* found via `engine.pid`.
2. **Evidence.** engine.log 22:08:51 → 00:08:53 (A's orphaned lean executor outlived A by two hours under engine B).
3. **Current code path.** Resume preflight `:285-317`; `_kill_pid_tree` `lib/common.sh:862-888`; the only existing ownership-aware reap `goal-iter-lean.sh:1036-1039` (`kill -0` + `ps -o args=` cmdline predicate).
4. **Root cause.** No descendant accounting for a dead engine.
5. **Invariant.** At lock acquisition no process carrying a provably-dead engine token for this session is alive; processes that cannot be attributed by token are reported, never killed by default.
6. **Proposed change.** `engine_orphan_sweep <session-dir> <sid>` (in `lib/engine-identity.sh`; knob `CHAIN_ORPHAN_SWEEP=true`), called in the prologue after the lock and BEFORE any port or channel mutation, same-uid only (`/proc/<pid>/environ` is unreadable across uids — the correct boundary): for every `/proc/[0-9]*` except `$$`, its ancestors (never the pump), FRESH sibling lock holders and their descendants — read `environ`; **kill rule (deterministic; BOTH conditions required):** (1) the process is attributed to THIS exact Goal session — its `environ` carries `GOAL_SESSION_DIR` whose canonical path (`realpath -m`) equals this session's canonical dir (same checkout, same session id; `GOAL_SESSION_ID` alone is not sufficient because the same id can exist in two checkouts) — AND (2) its `CHAIN_ENGINE_TOKEN` is set, ≠ ours, and `engine_token_alive` says provably dead ⇒ candidate root. A process attributed to another Goal session, another checkout, or whose session attribution is missing or ambiguous (no `GOAL_SESSION_DIR`, an unresolvable one, or two conflicting attributions) is NEVER killed by the token rule — it is only reported (`orphans_reported {rule:"foreign-or-unattributed", pid, cmd}`); tree-kill the roots (`CHAIN_ORPHAN_KILL_GRACE_SECONDS=5`), log `Orphan sweep: reaped N process(es) left by dead engine <token> (pids …; cmds: …)`, telemetry `orphans_reaped {count,engine_tokens,pids,cmds,survivors,detected_at:"preflight"}` (emitted with explicit `GOAL_SESSION_DIR`, as the machine-reset event at `:301-302`), `hg_event orphans_reaped`; survivors after KILL ⇒ WARN, continue (operational, no pause). **Legacy heuristics are report-only by default** (`CHAIN_ORPHAN_SWEEP_LEGACY=report|kill|off`, default `report`): (i) `environ` has `GOAL_SESSION_DIR=<this dir>` but no `CHAIN_ENGINE_TOKEN` (pre-token executor) and no live `run-goal.sh` ancestor; (ii) cmdline `run-goal.sh … --session-id <sid>` and pid ≠ `$$` (a fork-only subshell of a dead engine — `/proc/<pid>/environ` is the exec-time image, so such subshells never carry the token; their exec'd children do and are caught by the kill rule). Report mode logs `Orphan sweep: N unattributed process(es) look like leftovers of this session (pids …; cmds …) — not killed (CHAIN_ORPHAN_SWEEP_LEGACY=report); stop them by hand or set =kill` and emits `orphans_reported {count,pids,cmds,rule}`. Promotion of a legacy rule to `kill` requires a narrow, proven predicate and its own review (a stop-and-ask item), never a broad `/proc` heuristic becoming default kill authority.
7. **Files.** `lib/engine-identity.sh` (`engine_orphan_sweep`), `run-goal.sh` (prologue call site), `docs/TROUBLESHOOTING.md` (orphan sweep + report-mode remedy), `tests/automation/test-orphan-sweep.sh` (new), `run-evals.sh:202`, telemetry doc.
