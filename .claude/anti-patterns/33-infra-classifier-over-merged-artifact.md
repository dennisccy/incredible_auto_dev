## 33. A provenance-blind classifier run over a merged artifact launders "never verified" into PASS

**Applies to:** any post-scan, gate or headline that answers "what happened to the thing THIS dispatch owed?" — browser-infra attribution, fresh-evidence coverage, any verdict computed after two evidence sources were merged with later-wins.

**Pattern:** the REL-14 post-scan classified browser-infra failure with a whole-file predicate — "any PASS/FAIL row anywhere → not infra" — and both executors ran it over the MERGED `ui-test-results.md`, whose rows come from two sources: the deterministic replay lane (stable journeys, golden scripts) and the primary browser-qa dispatch (this iteration's targets). The merged headline was likewise "any surviving PASS row → PASS". So when the replay PASSed J-01/J-02 and Chrome never started for the targets J-04/J-13 (every target row `SKIP — Chrome did not become ready`), the merged file said `Browser QA Verdict: PASS`, no `browser-infra.json` was written, no `pending_infra` make-up was scheduled, and the evaluator was handed a PASS headline for targets that received no fresh browser evidence at all.

**Why it fails:** merging destroys provenance. After later-wins, a row no longer says which lane produced it, and a lane-agnostic reduction (`any(PASS)`, `no PASS/FAIL row anywhere`) cannot distinguish "the primary dispatch verified this" from "a different lane verified something else". The question the token and the headline must answer is per-journey and per-source: for each journey the PRIMARY dispatch owed fresh evidence for, what did THAT lane record? A PASS from a replay/stable journey must never suppress infra attribution for, or stand in for, a different required primary journey.

**Prevention:** classify the RAW primary artifact (`$_llm_out`), never the merged file, and classify per journey against the set the dispatch was actually asked to test (lean: `LLM_JOURNEYS`; full: targets ∪ the id-keyed regression set — the same set the token writer uses). Only the explicit browser-infra taxonomy in the journey's own row/section is infra; MISSING and non-infra SKIPs are never infra on their own; a sibling's PASS/FAIL never changes a journey's class. Make the merged headline honour the obligation: with `--required-primary` / `--primary-lane-floor`, PASS requires a fresh PRIMARY-lane PASS row for every owed journey and no primary browser-infra SKIP row; otherwise SKIPPED (a real FAIL stays FAIL) — same vocabulary, no new enum. Keep the generic merger byte-identical when no obligation is declared, so replay-only iterations, voids, DEFERRED-BUDGET rows and maintenance isolation keep their semantics. Rule: any classifier or headline over a merged artifact ships with the exact incident fixture (replay PASS + every owed target infra-SKIP) proving it cannot say PASS, and with the mixed fixture proving attribution lands only on the affected journeys (`merge_ui_test_results.py self-test`, `test-browser-infra-makeup.sh`, `test-browser-evidence-closure.sh`).

**Detection:** merged headline PASS while the raw primary lane file has no PASS row; `browser-infra.json` absent although the raw primary file carries the infra taxonomy; a `pending_infra` journey that never gets a make-up ride; evaluator prose citing a replay screenshot for a target journey.
